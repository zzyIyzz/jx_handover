# 江西片区智能交接班 V0.4.0 局域网服务器部署说明

## 一、先明确两台设备的职责

`\\192.168.14.52\江西片区检修中心` 只能存放文件，因此它不能直接运行本系统，也不能承载多人同时使用的数据库。正式部署还需要一台长期在线的 Windows 10/11 或 Windows Server 主机。

推荐结构：

```text
值班人员浏览器
        │ 访问 http://服务器固定IP:8765
        ▼
常开 Windows 主机
├─ 交接班服务器.exe
├─ 唯一正式数据库（本机固定盘；默认 ProgramData，可在控制器自定义）
├─ 导入原件、生成 Word 和快照（随正式数据目录）
├─ 设置、加密密钥、控制状态和日志（本机 ProgramData）
└─ 统一调用 qwen3.8-flash（Key 只在本机）
        │ 仅复制已完成的备份与网页快捷入口
        ▼
\\192.168.14.52\江西片区检修中心
```

不要把 `handover.db` 放到 NAS，也不要让多台电脑从共享目录运行服务器 EXE。SQLite 只允许服务器进程在服务器本地固定磁盘读写；所有使用者通过网页访问同一个后端。正式数据目录可以在第一次启动前自定义为 `C:`、`D:` 等本机 NTFS 目录，但不能填写 UNC、映射网络盘或正在同步的个人云盘目录。

## 二、服务器主机要求

- Windows 10/11 64 位或 Windows Server 2019 及以上。
- 固定局域网 IPv4 或稳定的内部 DNS 主机名。
- 值班期间持续开机，并关闭会让主机休眠的电源策略。
- 服务器到值班电脑之间允许 TCP 8765。
- 服务器可通过 HTTPS 443 访问阿里云百炼。
- ProgramData 和选定的正式数据目录位于本机 NTFS 固定磁盘并可正常写入。
- 服务器管理员账号可配置计划任务和 Windows 防火墙。

建议先由网络管理员给主机分配固定 IP。下文用 `192.168.14.60` 举例；实际部署必须替换成真实主机地址。

## 三、文件部署

1. 将 `江西片区智能交接班_局域网服务器_V0.4.0_win-x64.zip` 下载到常开主机本地。
2. 校验 ZIP 旁边 `.sha256` 文件中的 SHA256。
3. 完整解压到不会被云盘同步、不会随意移动的本地目录，例如：

   ```text
   D:\江西片区智能交接班服务器\V0.4.0
   ```

4. `服务器控制器.exe`、`交接班服务器.exe` 和 `_internal` 必须始终放在一起。
5. 不要直接从 ZIP 内运行，不要解压到 `\\192.168.14.52` 后运行。

## 四、第一次配置

1. 右键或双击 `服务器控制器.exe`，允许 Windows UAC 管理员提示。
2. 打开“服务器设置”。
3. 填写以下内容：

   - 局域网 IP 或主机名：例如 `192.168.14.60`。
   - 正式数据目录：默认 `%PROGRAMDATA%\JXHandoverServer`；也可在第一次启动前改成 `D:\JXHandoverData` 等服务器本地固定盘。
   - Qwen API 地址：默认百炼兼容地址；如单位使用业务空间专属域名，在此替换。
   - Qwen 模型：固定为 `qwen3.8-flash`。
   - Qwen API Key：由管理员填写，普通用户看不到。
   - 系统访问口令：建议不少于 8 位，只用于内网登录，不是 Qwen Key。
   - 管理员姓名：必须与系统人员名单中的姓名完全一致，多个姓名用逗号分隔。
   - NAS/云盘备份目录：例如 `\\192.168.14.52\江西片区检修中心\交接班系统\服务器备份`。

4. 先点击“测试当前配置”。控制器会验证填写的 IP 是否属于本机、正式数据目录能否安全落盘，以及当前登录账户能否在 NAS 执行备份所需的创建、改名、读取和删除操作；报告写入 `%PROGRAMDATA%\JXHandoverServer\deployment-tests`。
5. 点击“保存服务器设置”。
6. Key 和访问口令保存在：

   ```text
   %PROGRAMDATA%\JXHandoverServer\server-secrets.bin
   ```

   文件采用 Windows DPAPI 机器级加密，并限制为 SYSTEM 和本机 Administrators 读取。不要复制该文件到其他电脑；离开当前服务器后无法正常解密。
7. 如果需要接续 V0.3.0 单机版历史数据，请在第一次启动前先保存正式数据目录，再点击“迁移 V0.3 单机数据”，选择旧电脑复制过来的 `%LOCALAPPDATA%\JXHandover`、源码 `runtime` 或项目目录。控制器会：

   - 一致备份当前服务器数据库（如已有）；
   - 使用 SQLite 在线备份读取旧库及其 WAL；
   - 迁移导入原件、历史 Word 和快照；
   - 修正历史 Word 的服务器路径；
   - 保留迁移清单，下一次启动时自动升级数据库结构。

   迁移完成前不要启动服务器，也不要直接用资源管理器覆盖 `handover.db`。
8. 点击“启动服务器”，等待状态显示“运行中”。
9. 在服务器本机确认：

   ```text
   http://127.0.0.1:8765/api/health
   ```

10. 在另一台值班电脑确认：

   ```text
   http://192.168.14.60:8765
   ```

## 五、开机自动运行

推荐点击控制器中的“安装开机自动运行”，或在管理员 PowerShell 中执行：

```powershell
& '.\安装开机自动启动_系统账户.ps1'
```

脚本使用 Windows 计划任务，而不是注册表启动项：

- 触发条件为 Windows 开机。
- 账户为 `NT AUTHORITY\SYSTEM`。
- 不需要管理员登录桌面。
- 失败后自动重试三次。
- 同一时刻只允许一个任务实例。
- 同时创建仅适用于“域”和“专用”网络的 TCP 8765 入站规则，不开放“公用”网络。

控制器可以关闭，后台 `交接班服务器.exe` 会继续运行。控制器的“安全停止”会写入带当前实例标识的 `stop.request`；服务器完成手头请求后优雅退出，不会按 PID 强杀进程。

### SYSTEM 与 NAS 的重要限制

SYSTEM 通常没有访问远程 NAS 的用户凭据，因此：

- 服务器本地备份始终正常保留。
- 复制到 `\\192.168.14.52` 可能出现“拒绝访问”或“找不到网络路径”。
- 不要在脚本中明文保存 NAS 用户名和密码，不要使用带明文密码的 `net use`。

安全处理方式按优先级选择：

1. 由域管理员给这台服务器的计算机账户（`域名\服务器名$`）授予目标备份目录的“仅新增/写入”权限。
2. 使用单位批准的专用服务账号创建计划任务，并由管理员在 Windows 任务计划程序中安全保存凭据。
3. 如果没有域或服务账号，保留服务器本地自动备份，再由已有 NAS 权限的运维账号定期复制。
4. 最后备选才是 `安装登录自动启动_当前账户.ps1`；它能使用当前账号已保存的 NAS 凭据，但必须有人登录后服务器才启动，不是真正无人值守。

两个自启动安装脚本会自动移除另一种任务，并重新创建指向当前版本目录的域/专用网络防火墙规则，避免升级后同时启动两个版本。

## 六、生成所有人都能点的共享入口

1. 在控制器确认“局域网 IP 或主机名”正确。
2. 点击“生成共享盘网页入口”。
3. 选择：

   ```text
   \\192.168.14.52\江西片区检修中心\交接班系统
   ```

4. 控制器会生成：

   ```text
   江西片区智能交接班系统.url
   ```

5. 普通值班人员以后只需进入共享目录，双击该 `.url` 文件。无需下载 EXE、安装 Python、填写 Qwen Key，也不需要在自己的电脑上启动服务。

建议共享目录权限：管理员可修改，普通值班人员只读；避免普通用户误删或篡改网页入口和发布包。

## 七、运行数据、日志与备份

控制器设置、加密密钥、停止请求和运行日志始终保存在稳定的本机引导目录：

```text
%PROGRAMDATA%\JXHandoverServer
```

业务数据默认也位于这里；如果第一次启动前在控制器选择了 `D:\JXHandoverData` 等本地目录，则以下业务目录整体位于所选地址：

```text
<控制器中选择的正式数据目录>
├─ data\handover.db
├─ imports
├─ generated
├─ snapshots\database_backups
└─ logs
```

- 数据库只在服务器本机固定盘的 `data` 中运行；控制器会拒绝 UNC 和映射网络盘。
- 每日备份由服务器在长期运行期间定时检查，幂等地每天生成一次。
- NAS 配置成功时，只复制已经关闭并校验 SHA256 的备份文件。
- NAS 失败不会中断系统，本地备份仍保留，错误写入日志和备份清单。
- 运行日志默认保留滚动文件，排障时先点击控制器的“打开运行日志”。

建议再由单位备份系统每天同时保护 `%PROGRAMDATA%\JXHandoverServer` 和控制器选定的正式数据目录，并执行至少一次恢复演练。

### 已有数据后迁移到另一块本地磁盘

不能直接修改路径，否则会出现一套旧库和一套空库。正确流程是：

1. 在网页管理员面板点击“立即备份”，确认本地备份成功。
2. 在控制器点击“安全停止”，确认状态为“未启动”。
3. 点击“迁移正式数据目录”，选择服务器本地固定盘上的一个空目录。
4. 控制器会通过 SQLite 在线备份复制数据库，逐文件复制导入原件、历史 Word 和快照，并做完整性检查；全部成功后才修改设置。
5. 旧目录不会删除。启动服务器并完成登录、实际 Excel、Word 和 NAS 备份检查后，按单位数据管理要求保留或归档旧目录。

目标仍不能是 UNC、映射网络盘或个人云盘同步目录。

## 八、安全边界

- 本版只面向可信单位局域网，不得把 8765 端口映射到公网。
- 需要跨网访问时必须先接入单位 VPN，并另行部署 HTTPS/反向代理和正式统一身份认证。
- Qwen Key 只存在服务器，永远不写入前端、共享盘、ZIP、Git 或健康接口。
- 使用 AI 前应遵守单位数据合规要求；程序只把需要整理的最小业务文本发送给百炼，并保留人工预览确认。
- 访问口令用于降低共享内网误入风险，不等于互联网级身份认证。
- 不建议关闭“要求每位使用者选择姓名并输入访问口令”。

## 九、升级与回滚

1. 在控制器点击“安全停止”，确认状态变为“未启动”。
2. 先执行一次数据库备份并记录校验值。
3. 将新版完整解压到新目录，例如 `V0.4.1`，不要覆盖正在使用的目录。
4. 重新运行新版开机自启安装脚本，使计划任务指向新 EXE。
5. 启动新版并完成登录、Excel 导入、多人编辑、Word 生成和备份冒烟测试。
6. 数据始终位于控制器选定的本机正式数据目录，新版本程序目录不会覆盖历史数据。
7. 需要回滚时安全停止新版，再让计划任务指向旧版程序目录；不要回写或删除数据库。

卸载自动启动：

```powershell
& '.\卸载开机自动启动.ps1'
```

默认只删除计划任务，保留防火墙规则和所有数据。若确认不再使用，可在管理员 PowerShell 中加 `-RemoveFirewall`；数据仍不会被删除。

## 十、常见故障

### 浏览器打不开服务器

- 确认控制器显示“运行中”。
- 确认其他电脑能 Ping 到服务器固定 IP。
- 检查 Windows 网络配置为“域网络”或“专用网络”，不是“公用网络”。
- 检查计划任务和防火墙规则。
- 确认没有其他程序占用 8765；控制器不会强杀占用端口的程序。

### AI 显示未配置或连接失败

- 在服务器控制器重新填写 Key 并保存。
- 重启服务器使配置生效。
- 确认服务器可以通过 HTTPS 443 访问配置的百炼域名。
- 不要在值班人员浏览器中填写或复制 Key。

### NAS 备份失败

- 先确认本地 `snapshots\database_backups` 中已有备份；业务不会因此停止。
- 检查运行计划任务的账户是否拥有共享权限和 NTFS 权限。
- SYSTEM 无用户凭据是最常见原因，按第五节处理。
- 不要把正式数据库改到 NAS 以“绕过”备份问题。

### 安全停止超时

- 等待当前导入或 Word 生成请求结束后再试。
- 查看 `logs\server-runner.log` 和 `control\server-error.txt`。
- 控制器不会强杀服务器，避免在正在写数据库时造成损坏。
