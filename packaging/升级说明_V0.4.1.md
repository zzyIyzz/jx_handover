# 江西片区智能交接班 V0.4.1 升级说明

V0.4.1 是 V0.4.0 局域网多人版的生产加固测试版，重点解决“备份不完整、NAS 断开后不易补传、没有可操作恢复入口、升级容易覆盖旧版”四类风险。它仍部署在一台长期在线的 Windows 主机上；`\\192.168.14.52\江西片区检修中心` 只保存发布包、网页入口和校验完成的完整备份，不能承载运行中的 SQLite 数据库。

本测试版不创建正式 Git 标签或稳定 Release。现场完成真实数据、重启、NAS 断网和恢复演练并反馈后，再决定稳定发布。

## 一、本版新增

- 完整备份不再只有 `.db`：同一个 ZIP 内保存一致的 SQLite 数据库、导入原件、历史 Word 和脱敏配置说明。
- 本地生成完成后执行 ZIP、逐文件 SHA256 和 SQLite `quick_check` 三重校验，再复制到 NAS。
- NAS 断开时，本地备份照常完成并进入“等待重试”；NAS 恢复后可在网页一键补同步。
- 网页“系统管理”新增服务器健康、磁盘空间、数据库完整性、最近使用端、备份状态和服务进程身份。
- NAS 权限由真正运行服务器的进程身份测试，可识别“管理员控制器能写、SYSTEM 实际不能写”的差异。
- 新增备份与恢复中心：恢复前先全量校验，恢复只在下次安全重启、FastAPI 打开数据库之前执行。
- 每次恢复前自动再做一份 `pre-restore` 完整备份；恢复失败会把本次启动前的数据放回，并记录错误。
- 控制器可查看或取消待恢复任务、打开完整备份目录，并在恢复启动前再次确认。
- 控制器可校验新版 ZIP 与同名 `.sha256`，检查路径和 EXE 结构后解压到独立版本目录；旧版不覆盖、不删除，可直接回滚。
- 发布包新增 `release-info.json`，发布目录新增机器可读 `.release.json` 清单。
- 固定端口仍为 `8765`，Qwen 模型仍为 `qwen3.8-flash`，原一至六章和 6.1/6.2/6.3 均保持不变。

## 二、从 V0.4.0 升级

1. 在 V0.4.0 网页右上角进入“系统管理”，先创建备份；旧版只能备份数据库，因此还应确认服务器本地的 `imports` 和 `generated` 目录已由单位备份系统保护。
2. 取得以下三个同名文件并放在同一目录：

   ```text
   江西片区智能交接班_局域网服务器_V0.4.1_win-x64.zip
   江西片区智能交接班_局域网服务器_V0.4.1_win-x64.zip.sha256
   江西片区智能交接班_局域网服务器_V0.4.1_win-x64.zip.release.json
   ```

3. 可在 V0.4.1 控制器使用“校验并准备新版本”，也可人工核对 SHA256 后完整解压到新目录。新旧目录必须并列保留，例如：

   ```text
   D:\江西片区智能交接班服务器\V0.4.0
   D:\江西片区智能交接班服务器\V0.4.1
   ```

4. 用旧控制器点击“安全停止”，确认状态为“未启动”，再关闭旧控制器。
5. 打开 V0.4.1 目录中的 `服务器控制器.exe`。它读取相同的 ProgramData 设置和相同的服务器本地正式数据目录，不会把数据放进程序目录。
6. 启动 V0.4.1，进入网页“系统管理”，立即创建第一份 V0.4.1 完整备份，并检查文件数量、校验状态和 NAS 状态。
7. 依次验证登录、真实 Excel 预览、Word 生成、历史 Word 下载、两台电脑同时使用和安全重启。
8. 重新运行 V0.4.1 的自启动安装脚本，让计划任务与防火墙程序路径指向新目录。
9. 验证稳定前不要删除 V0.4.0 目录。

### 回滚到 V0.4.0

1. 用 V0.4.1 控制器安全停止服务器。
2. 关闭 V0.4.1 控制器，打开原 V0.4.0 目录中的控制器。
3. 启动旧版并验证。不要复制、覆盖或回写 `handover.db`；两个版本应指向同一个服务器本地正式数据目录。
4. 如需长期回滚，重新运行 V0.4.0 的自启动安装脚本。

V0.4.1 未新增数据库表或破坏性迁移，因此可回到 V0.4.0。若后续版本新增不可逆数据库结构，必须按对应版本说明处理，不能沿用本条。

## 三、从 V0.3.0 升级

1. 在旧版控制器安全停止 V0.3.0，确认 Word 和导入操作已经结束。
2. 把旧版 `%LOCALAPPDATA%\JXHandover` 完整复制到新服务器的临时本地目录。
3. 解压 V0.4.1 服务端包到服务器本地稳定目录，打开 `服务器控制器.exe`。
4. 第一次启动前点击“迁移 V0.3 单机数据”，选择复制来的 `JXHandover` 目录。
5. 等待数据库完整性、文件复制和历史 Word 路径修正全部完成。
6. 填写固定 IP/内网 DNS、服务器本地正式数据目录、Qwen Key、访问口令、管理员姓名和 NAS 备份目录。
7. 点击“测试当前配置”，启动服务器并完成真实 Excel、Word、多人冲突和完整备份检查。
8. 安装开机自动运行，在共享盘生成 `.url` 网页入口。

迁移不会修改旧电脑上的 V0.3 数据；如果新服务器已有数据库，迁移前会先创建一致快照。

## 四、恢复演练

首次正式上线前，至少在测试服务器或测试正式数据目录完成一次：

1. 创建完整备份并点击“重新校验”。
2. 新建一条仅用于测试的数据。
3. 对刚才的完整备份点击“安排恢复”。
4. 在服务器控制器点击“重启服务器”并确认恢复。
5. 检查测试数据已回到备份时状态，原班次、导入原件和历史 Word 均可用。
6. 检查备份列表中新增 `恢复前留底`，恢复结果为“完成”。

不要直接在正式生产数据上做第一次恢复演练；先使用测试机或单独测试目录。

## 五、重要边界

- 不要把 `handover.db` 放到 NAS、映射盘或个人云盘同步目录。
- 不要从 NAS 同时启动多个 `交接班服务器.exe`。
- 不要把 Qwen Key、访问口令或 `server-secrets.bin` 放入备份、共享盘或 Git。
- 不要把 TCP 8765 映射到互联网；跨网访问应使用单位 VPN、HTTPS 和正式身份认证。
- SYSTEM 默认可能没有 NAS 权限；请用网页“以服务身份测试”确认，不要只看控制器的交互账户测试。
- 完整备份 ZIP 与 `.json` 清单必须成对保留；不要手工修改 ZIP 内文件。

完整操作见同目录的 `服务器部署说明_V0.4.1.md`，现场逐项记录见 `现场部署测试清单_V0.4.1.md`。
