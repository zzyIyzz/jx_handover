# 江西片区智能交接班系统

当前版本：**V0.5.0 阿里云私有云部署测试版**

V0.5.0 在 V0.4.1 完整备份和可验证恢复基础上增加阿里云 ECS、Docker、宝塔 Nginx/SSL 与私有 OSS 部署路线。所有值班人员仍通过一个网址编辑同一份数据；完整一至六章、真实工作日志预览导入、Qwen3.8-Flash、原版式 Word 和历史版本均保留。当前云端版本必须位于单位固定公网 IP 白名单或企业 VPN 后面，尚不允许把共享访问口令直接开放给任意公网来源。

> 隐私门槛：本仓库既有历史版本包含内部场站和人员种子/演示信息。当前远端未登录也可读取，因此在完成历史脱敏前必须先把 GitHub 仓库设为 **Private**；只在新提交中删除文字并不能清除旧 Git 历史。真实 `.env`、API Key、业务数据库和实际工作日志始终禁止提交。

## 一、正式部署结构

推荐的新部署结构是“阿里云 ECS 本地数据盘 + HTTPS 私有入口 + OSS 异地备份”：

```text
每位值班人员的浏览器
        │  https://交接班域名（443）
        ▼
阿里云安全组 + 宝塔 Nginx/SSL + 固定 IP/VPN 白名单
        │  http://127.0.0.1:8765（只在 ECS 本机）
        ▼
一个 Docker 应用实例 / 一个 Uvicorn worker
├─ ECS 本地 ESSD 中的唯一 SQLite 正式数据库
├─ 导入原件、生成 Word、快照和本地完整备份
├─ qwen3.8-flash（Key 只在服务器 .env）
└─ 校验完成的 ZIP + JSON ── ECS RAM 角色 ── 私有 OSS
```

原 Windows V0.4.1 常开主机路线继续保留为局域网部署和回滚方案。`\\192.168.14.52\江西片区检修中心` 仍只是文件共享盘，不能直接运行服务或承载多人同时读写的 SQLite。无论用 Windows 还是 ECS，都不要把 `handover.db` 放到 NAS、OSS、SMB、WebDAV、同步盘或 FUSE 挂载目录；所有浏览器必须连接同一个后端服务实例。

## 三、Windows V0.4.1 最短部署流程

1. 准备一台长期在线的 Windows 10/11 64 位或 Windows Server 2019 以上主机，让网络管理员为它分配固定内网 IP 或内部 DNS 名称。
2. 把 V0.4.1 ZIP、同名 `.sha256` 和 `.release.json` 下载到该主机本地并核对 SHA256，完整解压到稳定的本地目录，例如 `D:\江西片区智能交接班服务器\V0.4.1`。
3. 双击 `服务器控制器.exe`，允许 UAC；在“服务器设置”填写：
   - 服务器固定 IP 或主机名；
   - 正式数据目录（默认 ProgramData，也可选择服务器本地其他固定盘）；
   - Qwen API Key；
   - 系统访问口令；
   - 管理员姓名；
   - NAS 备份目录，例如 `\\192.168.14.52\江西片区检修中心\交接班系统\服务器备份`。
4. 点击“测试当前配置”，确认 IP、正式数据目录、NAS 写入权限和 8765 端口；测试报告会保存到 ProgramData，便于现场反馈。
5. 如需接续 V0.3.0 历史数据，在第一次启动前点击“迁移 V0.3 单机数据”，选择旧版 `%LOCALAPPDATA%\JXHandover` 或源码 `runtime`；控制器会先备份、迁移原件/Word/快照并修正历史路径。
6. 保存设置并点击“启动服务器”。状态显示“运行中”后，在另一台电脑打开 `http://服务器固定IP:8765`。
7. 用管理员姓名登录网页，在“系统管理”创建完整备份，再点击“以服务身份测试”，确认实际服务账号可写 NAS。
8. 点击控制器的“安装开机自动运行”。它会创建 SYSTEM 计划任务，并只在 Windows“域/专用”网络放行 TCP 8765。
9. 点击“生成共享盘网页入口”，在共享盘生成 `江西片区智能交接班系统.url`。普通用户以后只需双击这个入口。

SYSTEM 通常没有远程 NAS 的个人凭据。若共享盘备份无权限，优先让域管理员给服务器计算机账户授予目标目录写入权限；否则可使用单位批准的服务账号。最后备选是“当前账户登录自启”，但它只有该账户登录后才会运行。

完整步骤、升级、回滚、防火墙和 NAS 权限说明见 [服务器部署说明 V0.4.1](packaging/服务器部署说明_V0.4.1.md)；第一次现场验证直接按 [现场部署测试清单 V0.4.1](packaging/现场部署测试清单_V0.4.1.md) 执行。

## 四、普通值班人员怎么用

1. 双击共享盘中的 `江西片区智能交接班系统.url`，或打开管理员提供的内网网址。
2. 选择自己的姓名；如果管理员启用了访问口令，再输入系统访问口令。
3. 创建或打开班次，按页面顺序填写完整六章。
4. 上传工作日志 Excel，先检查可编辑预览，再确认导入。
5. 完成第三、第四章复核，校验并生成 Word。

普通用户不需要安装程序、不需要填写 Qwen Key，也不直接接触数据库。人员下拉框、已选标签和 Word 中只显示姓名；岗位仍保存在人员接口和数据库中。

## 五、完整六章与人性化操作

网页和 Word 永远按以下顺序保留原章节：

1. 一、基本信息
2. 二、设备变更情况
3. 三、重点工作完成情况
4. 四、需交接的工作
5. 五、对外委单位的考核
6. 六、定期工作完成情况

第六章固定包含 6.1 月度、6.2 季度，并在其后追加 6.3 年度定期工作。

- 第一章自动保存；多人同时修改时使用 `revision` 检测冲突，页面会重新读取最新数据，不静默覆盖同事内容。
- 第二章支持快速添加、编辑、删除确认和撤销提示。
- 第三、第四章各自支持搜索、新增、编辑、改章、改状态、改优先级、排序和批量确认。
- 已完成事项默认建议进入第三章；未完成、进行中、受阻或待启动事项默认建议进入第四章。人工改章始终优先。
- 紧急为红、重点为黄、普通为白；优先级只控制颜色，不强制决定章节。
- 第三章保存完成人；第四章保存交接前责任人、交接后责任人和完成情况。
- 第五章支持外委考核新增、编辑、删除、排序和 XLSX 导入；无数据时 Word 仍保留三行空白占位。

## 六、实际工作日志与 Qwen3.8-Flash

用户提供的 `导入模板.xlsx` 已按实际结构完成本地适配和验收。它是连续工作日志，不是“三张业务表”的标准模板；系统会识别日期、场站、工作内容、期限、人员、完成状态、重点样式和每日进度，并按当前班次与当前场站筛选。

导入流程坚持“先预览、后入库”：

- 原 Excel 文件先保存在服务器本地，预览阶段不写第三、第四、第五章正式记录。
- 系统只把当前场站、当前日期窗内已经筛选出的最小预览文本分批发送给 Qwen；不会把整份工作簿直接上传。
- 模型固定为 `qwen3.8-flash`，使用严格 JSON Schema 和非思考模式返回结构化建议。
- 日期和人员由确定性解析器保留，AI 返回不能改写这两类来源事实。
- Qwen 超时、断网、Key 错误或输出异常时自动回退到本地规则，导入预览仍可继续。
- AI 只能整理预览，不拥有确认、发布或生成正式 Word 的权限；用户的最终选择优先。

Windows V0.4.1 中，Qwen Key 由服务器控制器使用 DPAPI 加密保存在 `%PROGRAMDATA%\JXHandoverServer\server-secrets.bin`；云端 V0.5.0 中，Key 只写入 ECS 上权限 `0600`、不进入镜像和 Git 的 `deploy/cloud/.env`。两种模式都不会把 Key 写入浏览器、健康接口、共享盘或业务备份。启用外部 AI 前仍应遵守单位的数据合规要求。

## 七、数据、备份与多人安全

控制器设置、加密密钥、控制状态和运行日志固定保存在 `%PROGRAMDATA%\JXHandoverServer`。业务数据默认也在这里；第一次启动前可在控制器改为 `D:\JXHandoverData` 等本地固定盘：

```text
<控制器中选择的正式数据目录>
├─ data\handover.db
├─ imports
├─ generated
├─ snapshots\full_backups
├─ snapshots\restore
├─ .r\b-*                      恢复时保留的启动前回滚目录
└─ logs
```

- SQLite 使用 WAL、外键约束、30 秒 busy timeout 和单 Uvicorn worker，适合当前检修中心的共享浏览器使用场景。
- 所有业务 API 在服务端模式下都要求登录；修改请求写入最小操作审计，不记录请求正文、访问口令或 Qwen Key。
- 事项、基本信息、设备变更、外委考核和定期工作使用乐观锁，旧版本提交返回冲突，不覆盖新数据。
- 数据库迁移前使用 SQLite 在线备份 API 生成一致快照，历史 Word 和 `DocumentSnapshot` 不重写。
- 每日完整备份在服务长期运行期间持续检查；ZIP 同时包含一致数据库、导入原件、历史 Word 和脱敏配置说明。
- 本地 ZIP、逐文件 SHA256 和 SQLite `quick_check` 全部通过后才复制到 NAS；失败任务保留为“等待重试”。
- 恢复只在安全重启、Web 服务打开数据库前执行；每次恢复前自动生成 `pre-restore` 完整备份，失败时回放启动前数据。
- 如果服务器本地数据丢失，可在停止状态下用控制器“从 NAS 导入完整备份并安排恢复”，ZIP 与同名 JSON 会先在本机全量校验；空白替代服务器无需先有数据库。
- 网页健康面板显示数据库、磁盘、备份、待同步、实际服务身份和 NAS 权限，管理员可校验、补同步或安排恢复。
- NAS 故障不影响业务；建议单位备份系统同时保护 ProgramData 引导目录和控制器选定的正式数据目录，并定期演练恢复。
- 已有正式数据时不能直接改路径；安全停止后使用控制器的“迁移正式数据目录”，校验通过才切换，旧目录保留。

Windows `server` 模式仍只面向可信单位局域网，不得把 8765 映射到互联网。V0.5.0 `cloud` 模式也不公开 8765，只能由 ECS 本机宝塔 Nginx 通过 HTTPS 反向代理，并强制使用单位固定公网 IP 白名单或企业 VPN。需要从任意公网来源访问时，先完成个人账号、独立密码和 MFA 升级。

## 八、源码运行与发布验证

V0.5.0 阿里云/宝塔云端部署：

```bash
sudo bash deploy/cloud/scripts/prepare-host.sh
# 编辑 deploy/cloud/.env
bash deploy/cloud/scripts/deploy.sh
```

完整步骤见 [阿里云宝塔部署说明 V0.5.0](deploy/cloud/阿里云宝塔部署说明_V0.5.0.md)。Compose 只把应用发布到宿主机 `127.0.0.1:8765`；生产用户只访问 HTTPS 域名。

V0.3.0 桌面源码模式：

```powershell
.\start.ps1
```

V0.4.1 服务端源码模式：

```powershell
$env:JX_HANDOVER_SERVER_HOME = 'D:\JXHandoverServerData'
.\.venv\Scripts\python.exe .\server_runner.py
```

后端回归测试（包含实际 Excel 存在时的可选本地验收）：

```powershell
$env:PYTHONPATH = 'backend'
.\.venv\Scripts\python.exe -m unittest discover -s backend\tests -p 'test_*.py' -v
```

前端生产构建与类型检查：

```powershell
Set-Location frontend
npm.cmd run build
npx.cmd vue-tsc --noEmit
```

构建 V0.4.1 Windows 服务端完整包：

```powershell
.\packaging\build_server_v041.ps1
```

脚本默认先构建前端、运行后端测试和 TypeScript 检查，再生成两个无控制台窗口的 EXE、完整 ZIP、SHA256 和机器可读发布清单。构建产物位于 `release`。真实工作日志、业务 DOCX、数据库、导入原件、Key、生成 Word 和服务器设置均不得提交到 Git。

版本变化见 [CHANGELOG.md](CHANGELOG.md)。
