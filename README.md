# 江西片区智能交接班系统

当前版本：**V0.3.0 人性化完整六章版**

这是面向风电、光伏场站的本地交接班工作台。它把 Excel 日志导入、事项复核、六章编辑、定期工作确认、Word 生成和历史版本留存在一个页面中完成。

系统只监听 `127.0.0.1:8765`，不会开放局域网访问。数据库是唯一事实源，网页是唯一编辑入口；日期、超期、颜色与章节结构均由程序校验，导入建议可以人工修改，人工选择始终优先。

## 一、普通用户：双击 EXE 即可

1. 下载 `江西片区智能交接班_V0.3.0_win-x64.zip` 及同名 `.sha256` 文件。
2. 把 ZIP 完整解压到任意新文件夹，中文路径和带空格路径均可。
3. 双击解压目录中的 `交接班系统.exe`。
4. 控制器会检查数据、启动服务、等待健康检查通过，并按设置打开浏览器。

控制器不显示黑色命令行窗口，提供以下操作：

- 启动系统、打开系统、停止系统、重启系统。
- 打开数据目录、打开日志、复制错误信息。
- 选择旧版数据目录并迁移数据库、导入原件、历史 Word 和快照。
- 显示“未启动、正在启动、运行中、停止中、启动失败”五种状态。
- 记住“启动成功后自动打开浏览器”选项。

最小化控制器不会停止系统。关闭窗口时会询问是否“停止系统并退出”。控制器只停止自己启动的服务，不会结束占用端口的其他程序。

## 二、数据位置与升级安全

正式 EXE 的所有用户数据都保存在：

```text
%LOCALAPPDATA%\JXHandover
├─ data\handover.db        SQLite 数据库
├─ imports                 导入原件与来源追溯
├─ generated               生成的 Word 与历史版本
├─ snapshots               数据库备份和文档快照
└─ logs                    控制器及服务日志
```

程序文件和用户数据分离。以后升级时解压新版程序即可，不会覆盖上述数据。数据库结构升级前会自动备份；旧版数据迁移前也会备份原数据库。

## 三、最省事的使用流程

### 1. 创建交接班

在工作台点击“新建交接班”，选择起止日期、交接日期和场站。系统会预填常用日期，并为所选场站建立独立的六章记录。

### 2. 填写一至六章

网页和 Word 始终按以下顺序保留完整结构：

1. 一、基本信息
2. 二、设备变更情况
3. 三、重点工作完成情况
4. 四、需交接的工作
5. 五、对外委单位的考核
6. 六、定期工作完成情况

第六章固定包含 6.1 月度、6.2 季度，并在其后追加 6.3 年度定期工作。

- 第一章自动保存。人员下拉框和 Word 只显示姓名；岗位仍保留在接口与数据库中。
- 第二章支持快速添加、编辑、删除确认和一次撤销提示。
- 第三章与第四章各自支持搜索、新增、编辑、改章、改状态、改优先级、排序和批量确认。
- 已完成事项默认建议进入第三章；未完成、进行中、受阻、待启动默认建议进入第四章。
- 紧急为红色、重点为黄色、普通为白色。优先级只控制颜色，不强制决定章节。
- 第五章支持外委单位、工作内容、考核情况、备注的新增、编辑、删除和排序；无记录时 Word 仍保留 1、2、3 三个空白占位行。

### 3. 预览导入 Excel

页面顶部点击“导入 Excel”，或在第三至第五章点击导入。系统提供标准工作簿，包含：

- `第三章-重点工作`
- `第四章-需交接`
- `第五章-外委考核`
- `填写说明`

上传后只生成可编辑预览，不会立即改动正式数据。页面会按工作表、行号、字段显示错误和警告；有效行可以继续提交，无效行不会落库。同一班次会识别重复内容并默认跳过，重复确认同一预览不会重复写入。

V0.3.0 同时包含实际工作日志适配器，可识别合并日期/场站、重点样式、人员、完成状态与每日进度。同一事项在班次内合并并保留最后一个工作日的状态；无法确定的信息会显示警告，交由用户确认。

### 4. 校验并生成 Word

生成前会检查：

- 第三、第四章事项是否已完成复核。
- 六个主章节是否各出现一次且顺序正确。
- 6.1、6.2 是否存在，6.3 是否位于其后。
- 七张表的表头、列数、数据行数与第五章占位行。
- 模板残留、空标题和 DOCX ZIP 完整性。

校验通过后才会生成 Word，并登记不可覆盖的历史版本。Word 使用经脱敏的原始交接班记录版式母版，保留标题、说明文字、字体、页边距、列宽、边框、底色和跨页表头。

## 四、端口与常见问题

系统固定访问：<http://127.0.0.1:8765>

| 现象 | 处理方式 |
| --- | --- |
| 双击后提示“系统已运行” | 控制器识别到同一系统，会直接打开网页。 |
| 提示 8765 被其他程序占用 | 关闭占用端口的程序后点击“启动系统”；控制器不会强制结束对方。 |
| 页面未自动打开 | 在控制器点击“打开系统”，并检查“启动成功后自动打开浏览器”。 |
| 启动失败 | 点击“复制错误信息”或“打开日志”，日志位于 `%LOCALAPPDATA%\JXHandover\logs`。 |
| 升级后没找到旧数据 | 停止系统后点击“选择旧版数据目录”，选择旧项目或其 `runtime` 目录。 |
| Excel 有错误行 | 按预览中的工作表、行号和字段提示修正；其他有效行仍可提交。 |
| 不能生成 Word | 按页面提示完成事项复核或补齐必填字段；结构错误会精确列出。 |
| 下载包完整性不确定 | 对 ZIP 执行 `Get-FileHash -Algorithm SHA256`，与同名 `.sha256` 文件核对。 |

## 五、源码运行与开发验证

源码运行仍可使用：

```powershell
.\start.ps1
```

前端生产构建：

```powershell
cd frontend
npm.cmd run build
```

后端全部回归测试：

```powershell
$env:PYTHONPATH = "backend"
.\.venv\Scripts\python.exe -m unittest discover -s backend\tests -p "test_*.py" -v
```

构建 Windows onedir + windowed 发布包：

```powershell
.\packaging\build_release.ps1
```

构建产物位于 `release`，包含完整 ZIP、SHA256、标准导入模板和升级说明。真实业务 Excel、原始业务 DOCX、数据库、导入原件和生成文档均不得提交到 Git。

版本变化见 [CHANGELOG.md](CHANGELOG.md)。
