# 江西片区智能交接班系统 V0.5.4 升级脚本

## 更新目标

- 仓库：`https://ghproxy.net/https://github.com/zzyIyzz/jx_handover.git`
- 分支：`release/v0.5.4`
- 目录：`/www/wwwroot/jx_handover`
- 服务：`jx-handover`
- 端口：`8765`

新版专门解决以下阻塞：

```text
[错误] 服务器项目目录存在未提交修改：
 M .env.example
为避免覆盖服务器文件，本次更新终止。
```

当唯一修改是 `.env.example` 时，脚本会先完整归档它，再继续更新，不会直接丢弃，也不会把旧模板自动覆盖回新版。

同时修复升级后 AI 仍显示未启用的问题：旧服务器 `.env` 中的
`AI_MODE=mock` 会迁移为 `AI_MODE=auto`，并优先保留当前 `.env` 中的
Qwen Key；当前配置没有 Key 时，会尝试从本工具生成的历史备份中安全找回。
密钥只写入权限为 `600` 的正式 `.env`，日志只显示末四位。

## 升级安全说明

- V0.5.4 分支已包含 Excel 修复；需要同时修复导入和 AI 时，先运行更新脚本，再按提示补充 Key。
- 若存在待执行数据库恢复，脚本拒绝继续；先在管理页核实并取消不需要的待恢复任务。
- 备份阶段会暂停现有服务，构建完成后重启；请安排维护窗口，并确认没有其他进程同时写入数据库。
- 同时备份当前 `runtime`、历史 `runtime-server` 和实际生效的自定义数据根；备份目录权限受限。
- 更新器也会实际测试 Qwen；连接失败会警告但不回滚已经完成的 Excel 修复。
- 数据恢复不是升级步骤。存在待恢复或 `applying.json` 时脚本会停止；请按 `../数据恢复操作与验收_V0.5.4.md` 核实处理。

## 仅恢复真实 AI

如果仅需恢复 V0.5.3 或 V0.5.4 的 AI 配置，可单独运行 `restore-ai.sh`；它不更新 Excel 导入代码：

```bash
chmod +x restore-ai.sh
sudo bash restore-ai.sh
```

脚本会按顺序寻找 Key：当前 `.env`、历史升级备份、终端安全输入。输入时
不会回显，也不会把真实 Key 写入 Git。配置完成后会重启服务并实际调用
Qwen 做一次连接测试。

也可以用非交互方式执行，但注意不要把命令保存到公开日志或聊天记录：

```bash
sudo env QWEN_API_KEY='真实的DashScope_API_Key' bash restore-ai.sh
```

真实 AI 生效必须同时满足：

```dotenv
AI_MODE=auto
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_MODEL=qwen3.8-flash
QWEN_API_KEY=真实且有效的DashScope_API_Key
```

若旧 Key 已经不在当前 `.env` 或任何备份中，程序无法凭空恢复密钥，必须
在阿里云百炼控制台取得一个可用的 DashScope API Key 后再运行恢复脚本。

## 执行方法

把 `update-jx-handover.sh` 上传到服务器任意目录，执行：

```bash
chmod +x update-jx-handover.sh
sudo bash update-jx-handover.sh
```

脚本文件必须保持 UTF-8、LF 换行。本文件夹中的版本已经按此格式生成。

## `.env.example` 的处理

若服务器仓库中只有 `.env.example` 被修改，脚本会在 `/www/backup/jx_handover/时间戳_进程号/` 保存：

- `.env.example.server-copy`：服务器原文件；
- `git-working-tree.patch`：未暂存修改；
- `git-index.patch`：已暂存修改；
- `git-status.txt`：修改清单；
- `git-stash-commit.txt`：Git stash Commit ID。

正式运行配置 `.env` 会单独备份并继续保留。更新完成后，如旧 `.env.example` 中仍有需要的值，请人工迁移到 `.env`，不要把旧模板整体覆盖回去。

查看归档 stash：

```bash
cd /www/wwwroot/jx_handover
git stash list
```

如果除 `.env.example` 外还存在其他业务代码修改、暂存文件或未跟踪文件，脚本仍会安全停止，并把状态和补丁写入本次备份目录；它不会强制覆盖这些未知改动。

## 其他升级点

- 默认发布分支为 `release/v0.5.4`；
- 所有非正常退出均经过统一回滚处理；
- 切换代码前即启用回滚标记；
- 仅允许 Git 快进更新，不抹掉服务器本地提交；
- 增加并发更新锁；
- 备份并可回滚 systemd 服务文件；
- 记录并恢复 `.env`、服务启用状态和服务运行状态；
- 自动把遗留的 `AI_MODE=mock` 迁移为 `auto`，并安全迁移当前或历史备份中的 Qwen Key；
- 更新结束后检查 AI 的请求模式、生效模式、模型和脱敏 Key 状态；
- 数据压缩包创建后立即校验；
- Python 镜像改用 HTTPS；
- npm 重试参数仅对本次进程生效，不修改 root 的全局 npm 配置；
- 健康检查使用随机临时文件；
- 旧备份清理仅匹配严格的时间戳目录。

## 可选参数

一般无需修改脚本。必要时可通过环境变量覆盖：

```bash
sudo env BRANCH=release/v0.5.4 PORT=8765 bash update-jx-handover.sh
```

支持：`PROJECT`、`REPO`、`BRANCH`、`SERVICE`、`PORT`、`BACKUP_ROOT`、`PIP_INDEX`、`NPM_REGISTRY_PRIMARY`、`NPM_REGISTRY_FALLBACK`。

## 回滚说明

部署失败时，脚本会尝试恢复更新前代码、依赖、前端构建、systemd 服务文件并重启服务。数据库和运行数据不会自动覆盖恢复，以免误覆盖仍在使用的数据；备份目录会在错误输出中明确显示。
