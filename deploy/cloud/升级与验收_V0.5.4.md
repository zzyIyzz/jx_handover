# V0.5.4 升级与验收

发布分支：`release/v0.5.4`。包含 Excel 异常样式兼容、多月份早晚班会识别，以及服务器 AI 配置恢复工具，不重置个人密码。

## 升级前

- 创建完整备份，记录数据库实际路径、人员及交接班记录数量。
- 若管理页提示“已安排数据恢复，等待服务器重启”，先确认该恢复是否需要；不需要就点击“取消待恢复”。升级与 AI 恢复会重启服务，可能触发待恢复任务。
- 不要随意切换 `runtime` 与 `runtime-server`。需要固定数据根时，将已确认的当前路径写入 `.env` 的 `JX_HANDOVER_DATA_DIR`。

## systemd / 宝塔升级

将本分支 `deploy/cloud/scripts/` 中的 `update-jx-handover.sh` 和 `restore-ai.sh` 下载并上传到服务器项目目录之外，例如 `/root/jx-upgrade-v0.5.4`，执行：

```bash
cd /root/jx-upgrade-v0.5.4
sudo bash update-jx-handover.sh
```

默认项目 `/www/wwwroot/jx_handover`，服务 `jx-handover`，端口 `8765`。脚本拉取 `release/v0.5.4`，Excel 修复也会随升级部署。只有 `.env.example` 被修改时先归档再更新；其他未知源码改动会阻止自动更新。

旧 `AI_MODE=mock` 会迁移为 `auto`。若没有找到真实 Key，运行配套恢复工具，按提示隐藏输入 Key：

```bash
sudo bash restore-ai.sh
```

恢复工具会重启并实际测试 Qwen。测试通过前，不要把“配置保存成功”当成“AI 可用”。不要把真实 Key 写进示例文件或聊天。

## Docker 部署

上述工具仅用于 systemd。Docker 环境先备份并确认工作区干净，再拉取并切换 `release/v0.5.4`，用原有 `deploy/cloud/scripts/deploy.sh` 重建。在原 Compose 配置中设置 `AI_MODE=auto` 与真实 `QWEN_API_KEY`，通过管理页测试；不要运行 systemd 恢复工具。

## 验收

- `/api/health` 返回版本 `0.5.4`，管理员状态正常。若 `.env` 手动设置过旧 `JX_APP_VERSION`，删除旧覆盖值后重启，让版本从 `VERSION` 读取。
- 当前数据根与升级前一致，人员、密码及交接班历史保留。
- 管理页 Qwen 连接测试成功，实际模式为 Qwen；没有 Key 或连接失败时如实提示本地规则回退。
- 原先报 `expected ... Fill` 的 Excel 可以生成预览，抽查场站、日期、责任人和完成情况，确认后再正式导入；上传原件不被改写。
- 详见 [服务器更新后核对清单](服务器更新后核对清单_V0.5.4.md) 和 [脚本说明](scripts/升级脚本说明_V0.5.4.md)。

本地测试不能代替服务器真实 Key、网络、模型权限与生产数据的现场验收。
